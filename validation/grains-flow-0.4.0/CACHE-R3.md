# 0.4.0 显示缓存候选

精确基线为 `0e63acab22e4d19fbf513897fde16babc01a5468`。本轮只缓存相邻画面未改变的沙粒栅格；材质、粒形、引擎、调度、输入、音频、界面与版本均保持基线。它不能解决尚未通过的视觉目标，也不代表浏览器视觉或性能验收已通过。

## 为什么需要缓存

第二轮独立浏览器中，85%密集唤醒的完整回调最大19.5ms，原首轮为253.1ms；时间债约1.71秒回落，真实输入FIFO与部分步暂停/重启隔离通过。但自然短局仍记录到一次像素准备21.5ms，在约83.8秒、71,524粒时发生；该次模拟仅0.4ms。它是一个真实长尾，不代表像素准备每帧都慢，也没有证据说明同一视觉键被错误重复渲染。

现有代码在棋盘revision变化时重算整个显示栅格，包括没有移动的内部区域。本候选保留已有完整画面复用，只对确实需要重建的棋盘内部增加局部缓存。

## 规则与成本

- 显示器自行保存上一版颜色、材料及清除掩码；不增加或修改物理引擎的脏标志
- 对齐的数组每次比较4字节，尾部1–3字节单独处理；未对齐数组使用逐字节扫描
- 源格变化标记其8×8显示瓦片，并扩展一圈瓦片。当前材质最远影响输出x±3、y−3至+4，因此一圈8格覆盖足够；未来改变材质依赖范围必须重验
- 最多25%输出瓦片局部重画，使用同一直接材质判定；超过阈值退回原有全量流程。空格明确写回背景，避免残影
- 首次使用、棋盘身份/尺寸、像素缓冲身份、配色、清除高亮模式及ready场景切换均正确失效。显式重画也清空缓存
- Canvas上传与最终合成保持原流程；没有声称实现局部GPU上传，也没有调整完整回调计时边界

288×432下固定增加377,136字节缓存，复用且不逐帧增长。全量回退有比较/复制开销，因此不是所有密集帧都更快。冷启动、Canvas上传、浏览器绘制长尾仍需独立测量。

## 检查与已知边界

独立原型Node测量中，实际R2物理轨迹的像素准备中位数：连续注沙1.48→0.53ms、顺坡3.18→0.80ms、密集唤醒5.00→4.82ms。密集的同帧全量回退额外开销中位数约0.47ms。Canvas为桩，不代表浏览器帧率或屏幕响应。

原型3,800次原始栅格对比约5GB完全一致，33项生命周期检查通过；已覆盖奇数尺寸、尾字节、输入数组替换与未对齐、清除与减少动态、配色、ready切换、精灵/落点、缩放、显式重画及同尺寸像素缓冲替换。集成源码另运行相同对照，结果摘要见下文。

最终集成源码通过50项基础、102项细沙回归及56个脚本语法检查；另有33项生命周期和1,900次/2,499,645,600字节的参考画面对比通过。集成时钟复测中，注沙median为3.13→0.75ms，顺坡2.62→0.76ms；密集唤醒median反而6.78→7.10ms（mean6.89→5.67ms）。注沙缓存路径最大69.89ms，高于该段R2的35.35ms，不利样本保留；本轮有同时执行的语法检查，无法据此给单次峰值作可靠归因。它不支持“所有长帧已解决”，独立浏览器必须重新测长尾。

冷进程测试没有消除长帧：空盘首次构建中位数仍约18.8ms；密集首次构建约40.7→30.6ms；ready后的密集首次构建约19.1→18.1ms。共享Node环境中的数字不能证明浏览器冷路径通过。

## 独立浏览器复验

使用普通单页游戏，分别测原基线和候选的固定密集唤醒、相同种子/输入短局及实际可见活动块输入。记录完整callback、pixelBuild、上传/合成、帧gap、债务、模型年龄和事件到首个变更画面；保留不利长帧及清除/配色转场。强制全量重画与缓存输出应逐像素相同，不能只比静止截图或rAF数量。

本候选保留R2材质，正常尺寸下可辨沙粒形状的视觉目标仍未通过。后续形状设计应单独验证真实空隙、同色斜角连接和运动中的粒形稳定性。
